# Public UI review and plan, 2026-10-11

Two independent reviews of the `/map` UI, one by Codex (gpt-6.1-sol, high effort, full
report in `ui-review-codex-2026-10-11.md`) and one by Claude, plus research on design
practice, component libraries and comparable map products. This file is the merged
verdict and the plan. Codex's file holds the full evidence with file:line references.

## Verdict

The pure layer is sound: `client/filters.ts` (filtering, ranking, grouping, URL codec),
`queries.ts` (reads `listable_event`, venue-owned coordinates) and the `DESIGN.md` token
pipeline. Keep them.

The view layer is where the "plumbing" feeling comes from. `/map` keeps component state
by hand: it rebuilds the pills and panel with `innerHTML`, then patches back what the
rebuild destroyed (scroll position, collapsed sections, slider handlers, image state).
Every feature this session added another patch. Both reviews reach the same conclusion
independently: **move the reactive `/map` UI to React components on the stack the admin
already uses**, keep the server and the pure model, and redo the visual layer on
shadcn/ui primitives styled from `DESIGN.md`.

## Where the plumbing shows (both reviews agree)

| Symptom | Evidence | Root cause |
|---|---|---|
| `render({ recenter, pills })` flags, `pills: false` added only so the slider survives a drag | `client/map.ts:264`, `:369` | No component identity: rebuilding the pill row destroys the slider |
| Scroll save and restore, a `collapsed` Set, re-wiring `onclick`/`oninput` each render | `client/map.ts:257-259`, `:28`, `:361-376` | Same; state that a component would own lives in the DOM |
| Four different transition paths for one URL change (marker, link, form, Back) | `client/map.ts:239`, `:285`, `:302`, `:310` (Codex) | No single owner of "what changed and what follows from it" |
| Two `!important` rules and a `:not(.filters):not(.search):not(.radius)` chain | `styles.ts:57`, `:91`, `:185` | CSS fighting inline styles set by JS; the hit-area overlay that broke the slider lives here |
| Two design systems and two theme implementations | `theme.ts:10-44` vs `admin/ui/index.html:14-22`, `theme-toggle.tsx`; `styles.ts` template vs `admin/ui/styles.css` | Public UI grew outside the React/shadcn/Tailwind stack the repo already has |
| 285 green tests, yet both real bugs this session (slider overlay, hidden hover label) were interaction bugs | `test/map*.ts` check HTML strings and pure logic | No browser tests for `/map` |

## Bugs to fix regardless of the migration (all confirmed in code)

1. **The pin label can show a stale event.** The marker cache key is selection + count +
   category (`client/map.ts:205`), but the tile now renders the next event's title.
   Two searches that leave one comedy event each reuse the old tile. Regression from
   this session's label change. S.
2. **Submitting a filter or search drops the grouping.** The forms carry `when` and
   `free` as hidden fields, never `group` (`render.ts:63`). S.
3. **A failed load leaves the page empty.** The client replaces the server-rendered
   list with skeletons before the fetch (`client/map.ts:45`). If the fetch fails, the
   fallback the design promises is gone. M.
4. **Source links on the map skip the URL check.** The detail page uses
   `publicSourceUrl` (`source-url.ts:2`); the map emits `row.sourceUrl` after escaping
   only (`queries.ts:97`, `render.ts:213`). Escaping is not URL validation. S.
5. **Reloading an approximate venue's URL still moves the map** to its area centre
   (`client/map.ts:442` calls `reveal`, not `focus`), against `DESIGN.md`. S.
6. **The listing's "Next 7 days" link ends at the weekend** (`pages.ts:352`, `:381`). S.
7. **`.pill` has no `[hidden]` rule**, so Near me can show as an inert button when
   geolocation is unavailable (`styles.ts:32`). S.

## Recommendation

**Move `/map`'s interactive UI to React 19 + shadcn/ui + Tailwind 4, with nuqs for URL
state and mapcn as the map component base.** All but nuqs and mapcn are already
dependencies (`react@19.3.0`, `tailwindcss@4.3.3`, `radix-ui@1.7.0`, `shadcn@4.21.4`,
`lucide-react`). One component model for the public site and the admin, one token set,
one theme implementation.

| Concern | Choice | Why this over the alternatives |
|---|---|---|
| Components | shadcn/ui 4.21, **Base UI variant** for the public map | Copy-in code we own and restyle from `DESIGN.md`. The shadcn Drawer now uses Base UI with snap points; the Radix variant still wraps Vaul, which its author put in unmaintained mode (shadcn issue #8455). Codex suggested Vaul; the newer docs supersede that. |
| Map | **mapcn** copied in, on `maplibre-gl` 6.13 | shadcn-registry map components (Map, Marker, Popup, ClusterLayer, Controls), MIT, about 11.6k stars, built directly on MapLibre with an escape hatch to the raw map. Our tile markers, tints and declutter port to its `MapMarker`. Swap its default CARTO tiles (commercial use needs a licence) for our OpenFreeMap styles. `react-map-gl/maplibre` 8.1 is the fallback if mapcn's internals fight us. |
| URL state | **nuqs** with the plain React adapter | Replaces `parseFilters`/`toQuery` with one typed descriptor (`useQueryStates`), push or replace per action, and a server-side loader from the same parsers. Vercel's interface guidelines name this pattern: URL as state, deep-link everything. |
| Session state | `useReducer` (location, radius, sheet detent, collapsed sections) | One snapshot and a handful of local states do not justify Redux, Zustand or a query cache. Both reviews agree. |
| Server output | Render the same React components to HTML on the server (`renderToReadableStream` in `Bun.serve`) | Keeps the no-JavaScript list, SEO and first paint. Two ways to wire the client: hydrate (Codex), or mount fresh once data and map are ready (simpler, no hydration mismatch because the server lists every venue and the client lists the viewport). Decide in slice 1. |
| Phone sheet | shadcn Drawer (Base UI), non-modal, snap points `peek / half / full` | Replaces the hand-written drag handler (`client/map.ts:406-420`), which misses `pointercancel` and pointer capture. Must stay non-modal so the map keeps working. |
| Panel pieces | Accordion (group sections), Toggle Group (Type / Day / Venue, and the when pills), Slider (distance), Combobox (type with emoji), Item and Empty (rows, "No event selected") | Each replaces a hand-built control with an accessible one we can still style. |
| Browser tests | Playwright on `/map`: slider drag, hover label, collapse across a pan, Near me, Back/Forward, phone sheet | Both bugs this session would have failed one of these. |

Budget: the map entry is already 302 KB gzipped against a 320 KB target, plus a 146 KB
worker (Codex measured). React DOM adds roughly 45-60 KB gzipped. Either raise the budget
deliberately in `DESIGN.md` or lazy-load the expanded event and filters. Measure in
slice 1 before committing.

## Design direction: from "clean" to "premium"

What separates the two, from the research (Vercel Web Interface Guidelines, Interface
Playbook) and the nextdoor.company light-mode reference:

1. **Typography.** Use Inter (variable, self-hosted, subset to Latin and digits), the
   reference's face, instead of `system-ui`. Tabular figures for every time, price and
   distance. Three weights, used consistently. Group headings at the real `title` size
   instead of control size plus an `!important` emoji override.
2. **Edges from shadow, not border.** Pills, tiles and the panel get a layered shadow
   (`0 1px 2px` contact plus `0 4px 12px` ambient, low alpha) with a hairline at most.
   This is most of the reference's softness.
3. **Concentric radii.** Inner radius = outer radius minus padding, so nested shapes line
   up: panel 24, cards inside 16, thumbnails 12, pills full.
4. **One control language.** Every control 36 px visually with a 44 px hit area, from
   one `hitTarget` token instead of per-selector `::before` overlays.
5. **Motion tokens.** Two durations (150 ms, 250 ms) and one ease-out curve in
   `DESIGN.md`, transitions on `transform` and `opacity` only, never `transition: all`,
   everything off under reduced motion.
6. **Map chrome placement** (take the reference's components, not its layout):
   - top-left: List / Map toggle and search
   - right edge: a compact control column (zoom, locate, compass)
   - bottom-left: filters and the live count
   - right: the detail panel with a real empty state ("No event selected · Tap an event
     on the map")
7. **States designed, not defaulted.** Skeletons that mirror the final row, an error state
   that keeps the list, a sparse state, hover and pressed on every row.

These become `DESIGN.md` changes first (font, shadow scale, radius scale, motion tokens,
control height, chrome layout), then code, per `AGENTS.md`.

## Plan, in slices

Each slice ends with `bun run check`, the Playwright suite and the screenshot matrix in
`DESIGN.md` (1280×800, 390×844, light and dark).

1. **Fix the seven bugs above on the current code**, each with a regression test. Add
   Playwright for `/map`. M.
2. **DESIGN.md v2**: font, shadow and radius scales, motion tokens, control height,
   chrome layout, empty and error states. Map its tokens onto shadcn's CSS variables
   (`--background`, `--primary`, `--radius`) so the admin and the map share one set.
   Merge the two theme implementations. M.
3. **React panel**: EventPanel, ResultsSection (Accordion), EventRow, EventImage,
   VenueDetail, server-rendered from the same components. The MapLibre code stays as-is
   behind a small adapter. Delete `renderPanel` and its `innerHTML` patches. L.
4. **React filter bar and URL state**: nuqs descriptor replaces `parseFilters`/`toQuery`;
   Toggle Group, Combobox, Slider, Near me with a pending state. M.
5. **Map and sheet**: mapcn Map with our markers and OpenFreeMap styles; Base UI Drawer
   for phones; one declutter pass per settled move. L.
6. **Polish pass** against the new `DESIGN.md`, then the listing page onto the same
   components. M.

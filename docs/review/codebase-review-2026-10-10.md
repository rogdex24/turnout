## 3. API and internal design

### Adapter contract and sync pipeline

`SourceAdapter` is appropriately small, and `FetchedItem.raw: unknown` is honest at the archive boundary (`src/ingestion/sources/types.ts:5`). The generic registry wrapper earns its place by applying one normalization pass with a consistent clock (`src/ingestion/sources/registry.ts:20`). Keep individual source parsers local; do not force HTML, RSC, JSON-LD and API pagination into one scraper class.

Fetches run sequentially outside the persistence transaction. Upsert, stale reconciliation, dedupe flag reset and raw pruning run in one SQLite transaction (`src/ingestion/sync.ts:74`). A write-phase throw rolls those writes back. Primary uniqueness is correctly source/record/slot-scoped (`src/catalog/schema.ts:58`). Failed adapter fetches are excluded from reconciliation; unhealthy source history includes only `ok` verdicts, so repeated degradation cannot lower its own baseline (`src/ingestion/sync.ts:148`). These are substantive protections, not just comments.

**Medium, fix before deploy: health history is committed before event persistence.** `src/ingestion/sync.ts:65`, `src/ingestion/sync.ts:177`. If upsert subsequently fails, `sync_run` becomes failed but its per-source `ok` rows remain eligible for future health medians. A large failed ingest can therefore make smaller real successful snapshots look degraded. Join health history to successful completed parent runs, or record source verdicts in the persistence transaction. Keep a failure record for diagnosis, with explicit fetch versus persist outcomes. This path is verified statically, not fault-injected.

**Medium, fix before deploy: overlapping syncs are allowed and fetch snapshots can complete out of order.** `src/ingestion/sync.ts:57`, `src/ingestion/sync.ts:63`, `src/ingestion/sync.ts:233`, `src/ingestion/sync.ts:319`. Start A with an old snapshot, let B fetch and commit a newer event, then allow A to finish: A can overwrite B's fields and count B-only rows as missing. SQLite serializes writes, not the preceding fetches. Use an atomic single-run admission/reservation with stale-run recovery, shared by CLI and admin; do not hold a DB write transaction open during network fetch. Cross-process timing was **unverified**; the missing admission and write semantics are visible in code.

**Low, fix before deploy:** `selectAdapters` silently ignores unknown names (`src/ingestion/sync.ts:374`), verified with `sources: ["typo"]` returning an empty successful run. Validate nonempty known source names in the CLI/admission boundary and report the offending name. All-source failure currently records parent success with errors and leaves the CLI exit status successful (`src/ingestion/sync.ts:83`, `src/cli.ts:117`). Define success/partial/failed with an exhaustive result type; exit nonzero when no requested source succeeded, while preserving useful partial data.

### Schema and migration behavior

`hasColumn` is a reasonable small additive mechanism today (`src/utils/db.ts:3`). Its interpolated table argument is from internal literals, not HTTP input; this is not an observed SQL injection. Fresh event schema has a venue reference, but upgrade adds a plain TEXT field (`src/catalog/schema.ts:71`), and the composition root does not enable foreign-key enforcement (`src/migrate.ts:11`). **Low, fix before more writers:** turn FK enforcement on for writable handles after auditing old rows, and explicitly test fresh and upgraded schemas. Add enum/boolean checks for status, category and canonical/free flags as new write paths arrive. Type casts and SQLite `strict: true` connection options do not substitute for table constraints.

**Low, fix before adding more data migrations:** category backfill treats every `other` row as unmigrated and reclassifies it on every startup (`src/catalog/schema.ts:90`). A later classifier change can alter old classifications at serve startup, bypassing the stated ingest-only decision. Add a migration version marker and run one-time backfills once; keep explicit reclassification a deliberate operation. `DROP VIEW` plus `CREATE VIEW` is also not wrapped in a composition transaction (`src/web/schema.ts:13`). Replace the view atomically to avoid a missing-view interval for concurrent readers. Concurrent-reader failure was **unverified**. Numbered forward migrations are worth introducing when the archive source-key or uniqueness migrations land, rather than layering more presence tests for data transformations.

### Public HTTP, caching and output

Public event reads consistently use `listable_event`; venue lookup only loads venue identity before querying events. Prepared query values and hardcoded column choices protect filters against SQL injection (`src/web/queries.ts:90`, `src/curation/mute.ts:60`). HTML text/attributes escape content, and JSON-LD escapes `<`, preventing injected closing script tags (`src/web/pages.ts:415`). Leave those mechanisms. Keep open CORS for public feeds as specified.

JSON responses cache for 60 seconds, shared feeds for 300; HTML specifies no cache directive (`src/web/api.ts:13`, `src/web/feeds.ts:99`, `src/web/pages.ts:12`). **Low, fix before deploy:** explicitly choose HTML revalidation/no-cache and document that a mute can remain in cached machine output for five minutes. Error JSON currently gets the same public cache policy. Use no-store for malformed-input/internal-error responses. A stable configured public origin is preferable to request origin for sitemap and event URLs (`src/web/feeds.ts:203`); Host/proxy cache poisoning in an actual deployment is **unverified**, so do not claim an exploit without proxy evidence.

**Low, fix before deploy:** routes ignore request method (`src/web/index.ts:78`), so POST and OPTIONS execute listing handlers. Permit GET/HEAD, handle HEAD without a body, and return 405 with Allow for other methods. There are no public writes today, so this is contract hygiene, not a current CSRF write vulnerability. The route table, explicit paths and small handler delegation are appropriate; leave them.

ICS uses CRLF, byte-counted folding, escapes text and substitutes a two-hour duration only when an event's end is absent/invalid (`src/web/feeds.ts:31`, `src/web/feeds.ts:74`). That fallback is documented and distinct from fabricating the start. It emits TZID without VTIMEZONE (`src/web/feeds.ts:21`); client interoperability is **unverified**. Prefer UTC DTSTART/DTEND for a small robust feed or add a correct timezone definition if retaining local TZID. Do not label current tests as calendar-client validation.

**Low, fix before asserting structured-data completeness:** adapters extract images but `Occurrence` discards them (`src/ingestion/sources/district.ts:114`, `src/catalog/types.ts:1`), public API emits null images and JSON-LD omits images entirely (`src/web/api.ts:161`, `src/web/pages.ts:304`). Alternate booking links are always empty (`src/web/api.ts:165`), despite stored dedupe members. Carry source image/attribution when permitted and derive alternate links from the group; make unavailable fields honest. Rich Results eligibility and image licensing are **unverified**; no external validator was called.

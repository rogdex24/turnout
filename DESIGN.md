# Hyd Tonight map

## Overview

`/map` shows this week's Hyderabad events on a quiet map. People use it on phones, often
outdoors, deciding where to go tonight. It should feel calm and exact: a muted basemap,
neutral square tiles for venues, one green accent that only ever means "selected" or
"act here".

**How to use this file (agents and humans).** Read it before any UI change to `/map`.
Use only the tokens in the front matter. Never invent a color, size, radius or shadow;
if a value is missing, add it here first, run `bun run design:lint`, then write code.
Every value is sourced: measured on the reference site, taken from a published spec, or
computed. When you cite a value in a commit or review, cite the token name.

Scope is the public map in `src/web/map/`, the server-rendered listing, category, area and event pages in
`src/web/site/`, and the shared component folder `src/web/ui/` (the brand lockup, the List / Map switch and the
shared chrome CSS). All of them read the one generated token block. The admin panel keeps its own
palette; it shares only the theme preference protocol (`src/utils/theme.ts`). The mobile app's `app-*` tokens
are in the Mobile app section.

Principles:
1. The map is the canvas, the events are the content.
2. One marker per venue, never one per event. Counts go in a badge.
3. Color never carries meaning alone. Category is an icon plus a word.
4. Show only what we know: no invented times, ratings or stock photos.
5. Fast on a mid-range Android over 4G: one self-hosted Latin font file, lazy images with fixed boxes.

Reference: nextdoor.company, measured with computed styles in a 1188 px browser on
2026-10-10:

## Colors

Token pairs with a `-dark` suffix are the same role in dark mode, applied under
`@media (prefers-color-scheme: dark)` and `[data-theme="dark"]`. Never derive dark values
by inverting.

- **primary** `#1f6f5c` / **primary-dark** `#6fcfb0`: the only accent. Selected ring,
  active pill, primary button, links. Never decorative.
- **map** `#f2f3f0` / **map-dark** `#0c0c0c`: read from the OpenFreeMap Positron and Dark
  style JSON. Do not restyle in CSS; contrast is computed against these.
- **surface**, **surface-glass**: pills, tiles, card, sheet. Glass is for the floating card
  with an 8 px backdrop blur.
- **ink**, **muted-foreground**: text. Muted is secondary text. The name matches shadcn's
  `--muted-foreground`, so the Tailwind utility `text-muted-foreground` is this color.
- **danger** / **on-danger**: destructive actions and errors only. Never decorative.
- **line**: decorative hairlines only.
- **tile-edge** `#7f888f` / `#6b757c`: the marker tile border; must reach 3:1 on **map**.
- **badge** / **on-badge**: count badge.

| muted-foreground on surface | 5.67 | 6.17 | 4.5 |
| primary text on surface | 6.02 | 8.38 | 4.5 |
| on-primary on primary | 6.02 | 9.15 | 4.5 |

**Roles map onto shadcn.** `src/web/map/tokens.ts` emits the standard shadcn variables from
the roles above, once for light and once for dark, and `src/web/ui/styles.css` exposes them
to Tailwind with `@theme inline`. Nothing else names a color.

| shadcn variable | Role |
|---|---|
| `--background` | **bg** |
| `--foreground`, `--card-foreground`, `--popover-foreground`, `--secondary-foreground`, `--accent-foreground` | **ink** |
| `--card`, `--popover` | **surface** |
| `--primary`, `--primary-foreground` | **primary**, **on-primary** |
| `--muted`, `--secondary`, `--accent` | **ink** mixed into **surface** at 4% (the hover tint) |
| `--muted-foreground` | **muted-foreground** |
| `--border`, `--input` | **line** |
| `--ring` | **primary** |
| `--destructive` | **danger** |
| `--radius` | `rounded.card` |

**Category is not a color.** Any marker can sit beside any other, the "all pairs" case.
The dataviz validator on its reference 8-hue palette with `--pairs all` fails: worst
colorblind separation 3.2 (needs 8), worst normal-vision 7.1 (needs 15), three hues under
3:1. Only three hues pass all-pairs and there are 11 categories, so every marker uses the
same neutral tile and the category is an icon. The icon tells categories apart by shape, not by
hue, so no two categories depend on telling colors apart.

## Typography

Inter, the variable font from `@fontsource-variable/inter` (SIL OFL), self-hosted as the
Latin subset plus a 1.2 KB rupee-sign face: `inter-latin-wght-normal.woff2` and `inter-rupee.woff2`
(U+20B9 alone, cut from the package's 85 KB latin-ext file by `scripts/subset-inter-rupee.sh`, because
latin has no rupee sign). Both are declared under one family name with a `unicode-range`, so a page
fetches the rupee file only when it prints a price. `font-display: swap`, served
from `/assets/fonts/` with a one-year immutable cache. There is no request to a font CDN.
The stack behind it is `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`, so text
shows at once and reflows only by a few pixels when the file arrives. Inter is the face of
the reference site. Weights in use are 400, 500 and 600 (see Do's and Don'ts).

Times, prices, distances, counts and badges use tabular figures
(`font-variant-numeric: tabular-nums`), so a column of numbers does not jitter as it changes.

| Token | Use |
|---|---|
| heading 20/26/600 | venue name in the card |
| title 18/24/600 | event title in an expanded row |
| body 16/24/400 | sheet and card body; search input (16 px stops iOS zoom on focus) |
| control 14/20/500 | pills, buttons, row titles (row titles at 600) |
| meta 13/18/400 | date, price, area, trust line |
| label 12/16/500 | marker label chip, captions |
| badge 11/14/600 | count badge, cluster "+N" |

Headings use `text-wrap: balance`. Venue names clamp to 2 lines in the card and ellipsize
at 160 px in a label chip.

Basemap: OpenFreeMap Positron (light) and Dark, URLs in one constant, with a light
repaint so the city reads at a glance: water is blue, green space is green, motorways are

them from the generated CSS variables and maps them onto layers:

transit labels below zoom 16. Zoom: min 10, default 11.5, max 18. Opening a venue (its tile

## Elevation & Depth

A shadow is two layers: a tight contact shadow that anchors the object and a wider ambient
shadow that lifts it. Three levels, nothing heavier. Alphas are percentages of the shadow
color:

| Level | Contact | Ambient | Color | Use |
|---|---|---|---|---|
| e1 | `0 1px 2px` at 5 | none | **shadow** | pills, search |
| e2 | `0 1px 2px` at 10 | `0 4px 12px` at 10 | **shadow** | marker tiles, location dot, toasts |
| e3 | `0 1px 3px` at 12 | `0 8px 24px` at 12 | **ink** | card, sheet, map frame |

The label chip keeps one layer, `0 1px 3px` at 20 of **shadow**. Each layer is
`color-mix(in srgb, <token> <alpha>%, transparent)`. Dark mode mixes **shadow** at 53% for
every layer of every level, because shadows read weakly on black. The selected tile sits
above other markers (z-order), not by a heavier shadow. Pills and cards get their edge from
the shadow plus a 1 px **line** hairline at most. Every surface takes its level from the table and nothing else: pills, search, the count, the control buttons and secondary buttons e1; marker tiles, the location dot and toasts e2; the card, sheet, popovers, the Combobox list and the map frame e3; a card inside the panel (the open event, a notice) e1.

Motion has three durations and one curve. Hover, press and pill state use `fast`
(150 ms). The sheet snapping to a detent and popovers opening (a fade and a 4% scale up from the anchor) use `base` (250 ms). The
camera takes 400 ms. The curve is `cubic-bezier(.2,.8,.2,1)` (ease-out) for everything but
the camera, which uses MapLibre's own easing. Transitions list the properties they change
(`transform`, `opacity`, `background-color`, `box-shadow`); `transition: all` is not used.
Under `prefers-reduced-motion: reduce` all become instant.

## Shapes

Radii are concentric: an inner radius is the outer radius minus the padding between them,
so nested shapes share a centre of curvature. The scale is `rounded.panel` 24 (the map frame,
the card and the sheet's top corners), `rounded.card` 16 (a card inside the panel, popovers,
notices), `rounded.tile` 12 (marker tiles, thumbnails, covers), `rounded.sm` 8 (inputs in
popovers), `rounded.xs` 4 (an image inside a tile) and `rounded.full` (pills, badges, buttons,
avatars). A panel with 8 px padding around a card gives 24 - 8 = 16, and a card with 4 px
padding around a thumbnail gives 16 - 4 = 12. Squares are for places (tiles, thumbnails);
circles are for people (avatars) and counts (badges).

## Components

Every component lists its states. Build all of them, not only the default.

**Control height.** Every control, pill and button is 36 px high (`control`, `pill`,
`search-pill`, `button-danger`), with a 44 px hit area (`hit-area`) made by a transparent
`::before` that extends the target. The one exception is `button-primary`, the "View on
<source>" call to action in an expanded event, which stays 44 px. Adjacent controls are
8 px apart, so their hit areas overlap by 4 px at most and the nearer edge wins.

**Pill** (`pill`, `pill-active`): border 1 px **line**, e1. States: default, active,
hover (background `color-mix(in srgb, ink 4%, surface)`), focus (2 px **primary** ring,
2 px offset), disabled (50% opacity, no hover). Row gap 8.

**Filter row.** One row of 36 px controls, each with a 44 px hit area (the search input is
44 px tall inside its 36 px pill): search, the when presets, Free, Filters, Near me and, while it
is on, the distance slider. The presets (Tonight, This weekend, Next 7 days) are a group of links
and so is Free; every one is a link, so they work without JavaScript, and the one that
is on carries `aria-current="true"` and no other state attribute. Pressing the preset that is on
returns to the default window.

**Search pill** (`search-pill`): the text is a draft and does not enter the URL or the history
until the form is submitted (Enter). Submitting keeps the grouping and the other filters and
closes any open card. icon 18 px at 14 px from the left; clear button appears
when it has text.

**Marker tile** (`marker-tile`): 1.5 px **tile-edge** border, e2, category icon at 22 px (see Icons).
A venue with several categories shows the icon of its soonest event. The tile face is a
fade, not flat white: the category's `tint-*` mixed into **surface** at 18% (28% in dark)
at the top left, falling to plain **surface** at the bottom right (160°). The tint is the
same hue as the icon's glyph, so it reads as a soft glow behind it. It is decoration only:
the icon and the label carry the category, so two tints never need telling apart.
Clusters and the selected ring stay neutral. States:
default; hover on pointer devices (translate up 2 px); focused (2 px **primary** ring);
selected (`marker-tile-selected`: 48 px, 3 px **primary** ring outside the edge, label
chip always shown, raised); loading (shimmer skeleton at 40 px).

**Count badge** (`count-badge`): when a venue has more than one event in the current
filter. Min-width 18, horizontal padding 5, positioned 7 px outside the tile's top-right.

**Label chip** (`label-chip`): **surface-glass**, shadow `0 1px 3px rgb(0 0 0 / .2)`,
max-width 160 px with ellipsis, 6 px right of the tile. Shown at zoom 14 and up, and
always for the selected venue; hidden when it would collide with another label. On a
venue tile it names the venue's next event (soonest start), the same event that picks the
icon. Hovering or focusing the tile always shows the chip and adds a second line with
the venue name in **muted-foreground** at 400.

**Cluster**: venues within 50 px cluster below zoom 14. Up to three stacked tiles offset
6 px, a "+N" `count-badge` (venues beyond the first) and a `label-chip` caption "N events".
Tap zooms to the expansion zoom. The caption counts events, because events are the point.

**Approximate venue**: a venue whose exact spot is unknown gets no marker on the map, not
even a placeholder at its area centre, because a ring there would point at the wrong
street. It is listed in the panel like any other venue, its area line reading "~ Gachibowli,
exact spot not confirmed", and is selected by its venue id.

**Distance slider**: appears in the pill row right after "Near me" once it is on, and
goes away with it. A pill holding a shadcn Slider (Base UI: a 4 px track, a **primary** range
and a ringed thumb, 112 px wide, a 44 px tall hit area; arrow keys, Home and End work) and
the value "Within 4 km" in tabular figures. Range 1 to 25 km in 1 km steps, default 4.
Turning Near me on centres your location dot in the visible map (the map minus the card
or sheet) and frames the 4 km circle with an 80 px margin on every side. Dragging filters
the tiles, the list and the count live, once per animation frame; letting go (or the end of a
key press) frames the new circle the same way. Venues farther away are hidden, not dimmed. An approximate venue
counts from its area centre. The radius is not in the URL, because your position is not.
The radius is drawn on the map as a circle in **primary**: fill at 4% opacity and a
1.25 px dashed edge (3 on, 3 off) at 45%, under the place labels and the venue tiles. It
follows the slider live and goes away with Near me.

**Near me** is a toggle button (`aria-pressed`) with three states. Off: "Near me". Requesting:
disabled, `aria-busy`, labelled "Locating…" until the browser answers (8 s at most). On: pressed,
with the dot, the circle and the slider. Denied: the toast under States and the Filters popover opens.

**Filters popover.** The Filters pill opens a popover under it with Type as a shadcn Combobox
(type to narrow; each option is the category icon and the word), Area as a native select, Apply and
Clear all. Escape and a press outside close it, and focus returns to the pill. The pill is marked
**primary** while a type or area is applied, and shows "Filters ·". The popover, its Combobox and the
distance slider load on first use (the pill preloads them on hover or focus), so a visit that never
opens them never downloads them. Without JavaScript the pill is a native disclosure around a GET
form with the same fields.

**Location dot** (`location-dot`): where you are, shown only after "Near me" is on and
removed when it is turned off. A 20 px **primary** disc in a 3 px **surface** ring with e2,
and one soft ring of **primary** that grows to 2.5x and fades every 2 s. Under reduced
motion the ring does not animate. It sits above venue tiles, since you are often at one,
and never takes a click, so the tile under it still opens.

**Panel list**: under the heading, a "Group by" switch of three segments, Type (default),
Day and Venue, in `meta` type (a group of links; each segment is a link, `?group=day`,
`?group=venue`, type is left out of the URL, so it works without JavaScript and survives a
reload). The chosen one fills with **primary**. Switching keeps the camera and scrolls the list
to the top.
- Type: one section per category, largest first and "Other" always last, headed by the icon (18 px) and word at `title` size plus the count in **muted-foreground**. Rows leave the category out.
- Day: one section per IST day in date order, headed "Sun 11 Oct". Rows keep the category.
- Venue: the venue sections described under Venue card.
Sections are a shadcn Accordion (Base UI), several open at once, all open by default. In Type
and Day the whole header is the trigger and a chevron on the right turns to show the state. In
Venue the venue name is a link that opens the venue, so the trigger is the line below it
(area, event count, chevron); a link cannot sit inside a button. Collapsed sections stay
collapsed while the map moves and the list redraws, until the page reloads. Without
JavaScript every section is open.
In Type and Day, each row has a third line in **muted-foreground**: a 13 px map pin, the venue name
and, when Near me is on, the distance ("Pulse 7 · 0.6 km"), ellipsized on one line.
Inside a section, rows run nearest first when Near me is on, else soonest first.

**Counts.** Three numbers, each with one meaning. The panel heading counts the events in the
unobscured viewport (the map minus the card or sheet): "7 events in view". Until the map has
reported a viewport, the server-rendered list shows every match and the heading reads "9 events".
The floating count (wide screens; on a phone the sheet's heading is the count) is the number of
events and venues matching the filters, wherever they are, plus the unplaced events. One polite live region, visually hidden, announces the settled
viewport count after the map stops moving or a filter changes; nothing else is live, so a
distance slider drag does not talk.

**Focus.** An event row is a link that opens or closes the event. Activating it keeps keyboard
focus on that row: the row's link has `aria-expanded` and `aria-controls` naming the expanded
region. Opening an event from the list moves focus to its row inside the venue card. "All
events" returns focus to the first row or header of the venue it closed. Opening from a marker
leaves focus on the marker.

**Venue card** (`card`, desktop): **surface-glass** with blur, 1 px **line**, e3, scrolls internally,
max-height the frame minus 24 px. The panel's inset is 8 px (`card.padding`), so a row or card
inside it sits 8 px from the edge and its radius is `card` 16, concentric with the panel's 24.
Headings and text blocks add `spacing.3` (12 px) of their own, so their text is 20 px from the edge
and lines up with the thumbnails. Top to bottom: "All events" back `link`; venue name in
`heading`; area and event count in `card-meta`; event rows.

**Sheet** (`sheet`, phone): a shadcn Drawer (Base UI), non-modal: it never traps focus, dims the
page or ignores the map above it, and a press outside it does nothing, so the map stays pannable
while the sheet is open. It has three snap points, measured as the part of the sheet on screen:
peek 120 px (handle, "23 events in view", one row: at peek the Group by switch and the section headers are hidden so the first row sits right under the heading), half `50dvh`, and full `100dvh - 104px`, which stops below the
filter row (its 44 px hit areas end at 96 px) so every filter control stays reachable at every detent. A drag moves it to the nearest detent (a fast flick goes by speed), a
tap on the handle goes up one and wraps, and "Expand" and "Collapse" buttons (44 px, disabled at

dismissed. Handle 36 × 4 px, radius 2, **line**, 8 px from the top. Tapping a marker opens it at

list is the same content in a plain block at the bottom. The sheet loads only on phones.

**Event row**: one anatomy everywhere (type, day and venue lists, the venue card, the phone sheet).
A row is a link shaped like a small card (`event-row`): radius `card` 16, 4 px of padding above
and below (`event-row` padding) and `spacing.3` (12) at the sides, so the thumbnail's 12 px radius
is the row's 16 minus its 4 and the thumbnail lines up with the heading text. The thumbnail
(`event-thumbnail`) and the text sit `spacing.3` (12) apart. The text is up to three lines, each
`spacing.1` (4) from the next and nothing else adds space between them: the title in `control` at
600 with a 2-line clamp, the meta in `card-meta` ("Sat 12 Oct · 7:00 PM", or "Sat 12 Oct" when the
source gave no time; price "Free" or "from ₹499"; category word), and, in the type and day lists,
the venue line. Rows are `spacing.2` (8) apart, and the height is at least `event-row` height (64).
States: default, hover, pressed, expanded, loading skeleton.

Meta parts read apart like syntax highlighting, by weight and tone, never a new hue:
date in **ink** at 500; time in **ink** at 400 with tabular figures; price in **primary**
at 500 with tabular figures, the word "from" in **muted-foreground** at 400; category as its 14 px

decorative; nothing else borrows that exception.

**Icons**: two families, one job each. Lucide (ISC license) as inline SVG for UI controls, 16 px inline,
stroke 1.75, color inherits from text. Categories use Phosphor duotone (`@phosphor-icons/core` 2.1.1, MIT,
a dev dependency whose license text ships inside the sprite), so the map has some life without category hues:
comedy `microphone-stage`, music `music-notes`, theatre `mask-happy`, workshop `palette`, sports `sneaker-move`,
food `bowl-food`, nightlife `martini`, community `users-three`, kids `puzzle-piece`, film `film-slate`,
other `sparkle`. The map from category to glyph is `CATEGORY_ICON` in `src/catalog/category.ts`, the one source.
Every place that names a category (tiles, rows, group headers, placeholders, the Type combobox on `/map`, the
listing rows and the event page) draws it through the one `CategoryIcon` component beside the word.

- **Delivery.** Icons are not in the JavaScript bundle. `bun run icons` (`scripts/build-category-sprite.ts`) reads the
  eleven duotone files and writes one SVG sprite of `<symbol id="<category>">` to `src/web/icons/categories.svg`,
  plus the hashed URL to `src/web/icons/spriteUrl.ts`; both are committed and a test fails when they drift from the
  package. The server serves the sprite at `/assets/icons/categories.<hash>.svg` with a one-year immutable cache, and an
  icon is `<svg><use href="<sprite>#<category>"/></svg>`. A page that shows no category never fetches it.
- **Colour.** The glyph is the category's `tint-*` mixed toward **ink** at 30% in light mode, and mixed with
  **icon-lift** (white) at 20%, so tint 80%, in dark mode. These are the two `--icon-toward-pct` values; the
  `category-icon` and `category-icon-dark` components name the colours. The duotone fill layer keeps the 20%
  opacity Phosphor gives it and follows `currentColor`, so it is the same hue, lighter. The tile and thumbnail
  tint fades are unchanged.
- **Size.** 22 px on a tile, 28 px on a row thumbnail, 40 px on a cover, 18 px in a group heading, 14 px in a meta
  line, 16 px in a combobox option. Placeholders draw the icon at 85% opacity.
- **Words.** A native `<select>` option cannot hold an SVG, so the listing's Type select and the no-JavaScript
  Filters form show the word only (`categoryLabel`). The Type combobox option shows icon and word.
- **Accessibility.** The icon is decorative (`aria-hidden`); the word beside it, or the tile's accessible name,
  carries the meaning. One icon per category, never stacked or animated.

## Do's and Don'ts

- Do keep one accent. **primary** means selected or "act here", nothing else, except the "Tonight" in the brand lockup.
- Do show the date without a time when the source gave none. Don't print "7:00 PM" as a
  guess.
- Don't color markers by category with solid fills. The faint `tint-*` fade on a tile is the
  only category color, and it never carries meaning alone.
- Don't draw any marker for an approximate venue, and don't place a pin at the city-centre
  placeholder point.
- Don't show a rating, review count or star row without real data. No "0 stars", no "New".
- Don't use stock photos or AI-generated images as event covers. A placeholder must look
  like a placeholder.
- Don't use more than three font weights (400, 500, 600) on one screen. The one exception is "Hyd" in the brand lockup at 700.
- Don't add shadows heavier than e3 or radii outside the scale.
- Don't open a new page when a marker is tapped; open the card or sheet.
- Don't let the page scroll sideways at any width.
- Do keep `/` free of the map bundle.

## Images, organisers and ratings

Measured on a full sync (2026-10-10): adapters keep image URLs for 4 of 8 sources:
BookMyShow `bannerUrl`, Communitie `portraitImageUrl` / `landscapeImageUrl` /
`previewImageUrl`, District `imageUrl` (vertical cover), MeraEvents `coverImageUrl`.
AllEvents, Luma, Townscript and Growezy keep none. Organiser names: only Communitie
`hostName`, on 5 of 54 events. Ratings: none from any source.

Event images:
- Store one `event.image_url` at ingest (landscape, then preview, then portrait), and only
  if it is an absolute https URL.
- Render with `loading="lazy"`, `decoding="async"`, explicit width and height, and
  `referrerpolicy="no-referrer"`. On error, swap to the placeholder with no layout shift.
- A vertical poster sits contained, centred over a blurred, darkened copy of itself, so it
  is not cropped. The copy is blurred 24 px and dimmed to 50% brightness.
- Images are hotlinked from the source CDN and the card always credits and links the
  source. Rehosting is an open question for the operator (rights).

Placeholder: the same box, a neutral tint picked deterministically from the event id (6
neutral steps, never category hues), the category icon at 85% opacity in the centre. The 6
steps are **ink** mixed into **surface** at 5, 8, 11, 14, 17 and 20%. The loading skeleton
uses step 2 with a sweep of step 4.

Organiser avatar placeholder: up to two initials on a neutral tint from the name, **ink**
at 70%. When there is no organiser, the block shows the venue instead.

Ratings: until a source provides them, the trust line uses facts we hold, for example "12
events this month · on 2 sources".

Data needed now (additive columns): `event.image_url` and `event.organiser_name`. An
`organiser` table (`id`, `name`, `name_key`, `source`, `avatar_url`, `rating_value`,
`rating_count`, `rating_source`, linked by `event.organiser_id`) waits until a second
source sends organisers or any source sends ratings; one source with 5 names does not
justify it.

## States

- Loading: skeleton shimmer at final size for tiles and rows, for at most 1.5 s.
- Empty: keep the map, card "No events match. Clear filters" with the action.
- Empty area: the map is panned or zoomed to a place with no events but some match elsewhere. The
  card says "No events in this area", "N events match elsewhere on the map." and a "Show all"
  button that fits the map to the matches. It is not "No events match", which is for no matches at all.
- Location denied: toast "Location is off. Pick an area instead", open the area filter.
- Map failed (WebGL, the basemap style or its tiles): the server-rendered list stays, with one
  line saying the map could not load and a "Try again" button that starts the map again. The map
  is given 20 s to be ready; a style that fails or a timeout both end here. A theme change whose
  basemap fails to load keeps the basemap on screen and shows nothing: it is not a failure.
- Every state is previewable with `?state=loading|empty|error|denied` so screenshots can
  cover it.

## Accessibility

- Every marker is a focusable button named "<next event>, at <venue>, <category word>, <n>
  events" (the icon is decorative), reachable by Tab. The list is an equivalent route to every marker.
- Focus ring 2 px **primary**, 2 px offset, never removed.
- All text and non-text pairs meet the Colors table.

## Mobile app

The Turnout app (`apps/mobile`) has its own palette and type scale in this file, under the `app-` prefix. Every web and
`/map` token above is unchanged; `primary` stays `#1f6f5c`. `src/web/map/tokens.ts` leaves the app tokens out of the page's
CSS, and `scripts/build-mobile-tokens.ts` turns them into `packages/design-tokens` (`bun run tokens:mobile`). The reference
mockups and the full spec are in `docs/design/mobile-final/`.

Direction: Nightlife in Gallery Night. A warm near-black and a warm paper, ivory or ink for the one primary button,
and a single orange that only ever means something is live. The app follows the system theme; there is no theme toggle.

- **Orange is the live signal and nothing else**: finding your group, "In 48 min", the thread is open, someone just arrived.
  Never a price, a count, a button or a heading.
- **Waiting and checking use `app-muted`**, not orange. Done states use `app-ink`.
- **Rejected and called-off states use the neutral note** (`app-surface-raised` with an icon). Never `danger`; the app has
  no red.
- **The live chip sits on `app-bg` or `app-surface`**, never on `app-surface-raised`: in dark the tint lowers the ratio there
  to 4.15.
- `app-signal-soft` is the signal at 8% (light) and 14% (dark). The mockups use 10% in light; at 10% the "In 48 min" chip
  falls to 4.97 on `app-bg`, below the 5.1 target, so light uses 8%.
- `app-pressed` (ink at 8%) and `app-skeleton` (the `app-surface-raised` tone) are not in the mockups; they are derived from
  its ink and raised surface.
- Text on a poster or photo is `app-on-photo`; the placeholder poster tones are `app-poster-comedy`, `-music` and `-theatre`.
- The marquee band is dark in both themes; its text is `app-ink-dark`.

counts and codes use tabular figures. Radii (14 fields and faces, 16 cards, 20 the featured card, 24 sheet top, pill), spacing in

### Bundle budget

Measured 2026-10-11 on the vanilla map (`buildMapAssets()`, each file gzipped):

| File | Raw | Gzip |
|---|---|---|
| `map.js` (MapLibre, glue, client code) | 1,072,831 B | 302,341 B |
| `maplibre-worker.js` | 508,314 B | 146,240 B |
| `map.css` | 83,145 B | 10,739 B |
| First load total | 1,664,290 B | 459,320 B |

React DOM costs 67,725 B gzipped in production mode (`hydrateRoot` plus `useReducer`, built
with `bun build --minify --production`; a development build is 131,220 B and must never
ship). The old limit of 320 KB on `map.js` cannot hold with React, and the S2 limits (400 KB for
the entry, 560 KB for everything) held through S3 (554.7 KB) and broke in S4.

Measured 2026-10-11 after S4 (Bun `splitting`, each file gzipped):

| Part | Gzip | When it loads |
|---|---|---|
| entry `map.js` | 91,269 B | with the page |
| eager shared chunks (nuqs adapter, lucide, Base UI core for the accordion and toggles, React) | 28,366 B | with the page |
| MapLibre chunk | 291,004 B | right after hydration |
| `map.css` | 12,739 B | with the page |
| `maplibre-worker.js` | 146,240 B | when MapLibre starts |
| **first load** | **569,618 B** | |
| Filters popover chunk (Popover, Combobox, floating-ui) | 53,552 B | the first time the Filters pill is hovered, focused or pressed |
| distance slider chunk | 8,146 B | the first time Near me turns on |
| **on demand** | **61,698 B** | |
| every file | 631,316 B | |

The Popover and Combobox are most of the on-demand cost; nuqs and the S4 shell add about 5 KB
to the first load. The limits, each with about 2% headroom over what S4 measured:

| Limit | Value | What it covers |
|---|---|---|
| entry `map.js` | 400 KB | client code, React and the Base UI parts used on first paint (91.3 KB today) |
| first load | 580 KB | the entry, the chunks it imports, the MapLibre chunk, the CSS and the worker (546.8 KB after S7 follow-ups) |
| phone first load | 580 KB | first load plus the phone sheet chunk and the Base UI code it imports, which every phone fetches at load (577.9 KB) |
| on demand | 70 KB in all | chunks behind a dynamic import that waits for a click: the Filters popover, the distance slider and any later one (41.4 KB) |

The phone chunks used to be counted as on demand, which hid that a phone fetches them at load; they now
count against the phone line, which is the stricter one. Getting both lines under 580 KB took three
trims, not a bigger budget: MapLibre's stylesheet loses the rules for controls we do not draw (zoom,
compass, geolocate, fullscreen, globe, popup, scale, logo, group; 9.4 KB gzipped, the attribution
button's icon stays), and the when presets, Free and Group by are plain links in a `role="group"`
instead of Base UI Toggle and Toggle Group (they were links already, with the toggle state removed and
the tab stop forced), which drops Base UI's composite and floating-ui helpers from the first paint.

`/` and the other listing pages load no map JavaScript. A visit that never opens Filters and
never turns on Near me downloads only the first-load line. Remeasure at the end of every slice
and record the numbers in the progress note; `test/mapBundle.test.ts` fails when a line is crossed.

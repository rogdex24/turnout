# Accessibility (A24)

What the tests check, what they cannot, and the steps the owner does by hand on a phone.

## What the tests check

Run with `bun run test` in `apps/mobile` (or `bun run check` from the repo root).

| Check | Where | What it catches |
| --- | --- | --- |
| Every pressable has a role and a label | `src/a11y.test.tsx` | It renders every story state under `src` (the view for each screen and each state of it) and the sheets that open from a view (safety, thread report, after-show confirm). A pressable with no `accessibilityRole`, or a pressable, switch or text field with no `accessibilityLabel`, `aria-label` or `accessibilityLabelledBy`, fails with the story title and the test ID. The file also feeds the check a bad pressable, to prove it can fail. |
| Reduce Motion | `src/ui/reduceMotion.test.tsx` | `Sheet` fades instead of sliding when the setting is on, and follows a change while the app is open. The welcome carousel scrolls with `animated: false` when it is on. Haptic moments are skipped (`src/ui/moments.test.ts`). |
| Largest text does not clip a fixed-height row | `src/ui/largeText.test.tsx` | The buttons, the thread header and the Conversation row carry a minimum height (`min-h-*`) and no fixed height (`h-*`), so a label that wraps at the largest text size grows the row. A centred bar title (`BackBar`) keeps clear of the wider side and ends in an ellipsis, a Home day heading wraps its date under the title, and a poster title shrinks to leave room for the category line under it. The text scale used is `LARGEST_TEXT_SCALE` (2). The scaling caps per text style are in `textScale.test.ts` and `typography.test.ts`. |
| Contrast of every colour pair | `test/mobileTokens.test.ts` (root) | Each pair in the DESIGN.md contrast table is computed from the generated tokens in light and dark. The photo scrim and the selected chip are in that table. A pair under its target (4.5 for text, 3 for controls and the signal dot) fails. |

### Misses the checks found and what changed

- The story test found no pressable without a role or a label in the stories as they stand. It is there to keep it that way.
- Fixed heights that a larger text size would clip, now minimum heights: the primary and secondary `Button` (`min-h-14`, `min-h-12`), the thread header (`min-h-14`), the code boxes in `CodeEntry` (`min-h-16`) and the 112 call button on the report screen (`min-h-11`).
- The scrim under on-photo text in light mode was 45% ink, which measured 2.53:1 over a white photo. It is now 65% (`app-scrim: "#181818a6"`), which measures 4.76:1 over white in light and 4.97:1 in dark. DESIGN.md has the rule and the two new table rows (on-photo on the scrim, and bg on ink for the selected chip), and the tokens were regenerated with `bun run tokens:mobile`.
- The thread list was a `FlatList`. It is now a `FlashList` with item types (that is A25, but it changes what a screen reader walks through: the list keeps its label and the inverted order).

### What the tests cannot check

- What TalkBack and VoiceOver say. The tests check that a name exists, not that it is the right one, nor the reading order, nor the focus after a sheet opens or closes.
- Text that is cut by `numberOfLines` at the largest size. The tests check rows, not each line. Look at it in the screenshots below.
- Reduce Transparency. The app has no blur and no translucent panel except the photo scrim, which is a plain colour, so there is nothing to switch off. Confirm that on the phone.

## Owner steps

Do these on the release-like build (`preview` variant) and write what you saw in the table at the end. A step that fails is a bug: open an issue with the screen and the setting.

1. **TalkBack on a real Android phone, through the whole loop.** Settings, Accessibility, TalkBack on. Do the loop with the screen on and your eyes off it: welcome, notice, phone number, code, profile (name, gender, photo), Home, a show, make the plan, wait in Plans, the reveal, the thread, the meet card, check in, after the show, the report sheet, sign out. For each screen check that:
   - swiping right visits every control once, in the order a sighted person reads it;
   - each control says what it is and what it does ("Share your phone number, button"), not "unlabelled" or a file name;
   - a sheet takes focus when it opens and gives it back when it closes;
   - the thread announces a new message, and the live chip on the plan announces a change of state;
   - nothing needs a gesture that TalkBack cannot do (long press, drag).
2. **VoiceOver on the iOS simulator with the Accessibility Inspector.** Xcode, Open Developer Tool, Accessibility Inspector, point it at the simulator. Run the Audit on each screen and read every finding. Then turn on VoiceOver in the simulator (Settings, Accessibility) and walk the same loop as above, checking the same five points. The simulator cannot show haptics or the keyboard dictation, so skip those.
3. **Largest text screenshots.** On each phone set the font size and the display size to the largest. Take a screenshot of every screen in light mode, and of Home, the plan and the thread in dark mode. Look for text that is cut off, buttons whose label is cropped, rows that overlap and a primary button pushed off the bottom of the screen. Attach the screenshots to the table.
4. **Reduce Motion.** Android: Settings, Accessibility, Remove animations. iOS: Settings, Accessibility, Motion, Reduce Motion. Walk the loop. Sheets should fade, the welcome carousel should jump, and nothing should slide, bounce or pulse that is not needed to read the screen.
5. **Reduce Transparency (iOS: Settings, Accessibility, Display and Text Size) and Increase Contrast.** Check the on-photo text on Home and on the show screen, over a bright photo and over a dark one, in light and dark mode. The text must stay readable over the brightest poster you can find. If it is not, the scrim in DESIGN.md changes first, then the tokens, then this table.
6. **Large touch targets and switch access.** With Switch Access or Voice Access on, check that a control with a visible label can be named aloud and that the label matches what the screen shows.

## Rules the code follows

- A control has a role and an `accessibilityLabel`.
- A row that holds text has a minimum height and no fixed height.
- A colour pair that is new is added to the DESIGN.md contrast table first, and `test/mobileTokens.test.ts` computes it.
- The live chip sits on `app-bg` or `app-surface`, never on `app-surface-raised`: in dark the tint lowers its ratio there (DESIGN.md says so).
- Motion reads `useReduceMotion()` from `src/ui/reduceMotion.ts`. A new animation or haptic checks it and has a case in `reduceMotion.test.tsx`.
